## 0. 확정된 설계 결정 (변경 가능, 추후 재검토 시 참고)

- **연습모드는 "몰입형" UI로 확정**: 앱 카드 안에 작은 기계 그림을 넣는 방식이 아니라, 연습모드 진입 시 화면 전체가 해당 매장의 키오스크 화면 그 자체처럼 보이도록 한다(배경/버튼 스타일까지 매장별 스킨 적용). 앱의 도움 요소(음성 안내, 진행률)는 화면 위에 떠 있는 최소한의 오버레이로만 존재한다.
- **실시간 안내 모드는 기존 앱 스타일 유지**: 실물 기계가 눈앞에 있으므로, 화면을 기계처럼 재현할 필요 없이 일반 앱 UI로 옆에서 돕는다.
- ⚠️ 이 결정은 프로토타입 단계에서 나온 방향이며, 실제 사용자 테스트 결과에 따라 바뀔 수 있음. 변경 시 이 섹션을 갱신할 것.

## 1. 전체 내비게이션 구조 (v1.1, 실제 구현 기준)

```
하단 탭바 (3개)
├── 홈 (모드 선택: "연습하기" / "지금 매장이에요", 저장된 내 주문 바로가기)
├── 내 주문 (저장된 주문 목록)
└── 설정 (접근성: 글씨크기, 음성, 고대비, 언어)

주문 흐름 (홈에서 스택으로 진입, 탭바 숨김)
홈(모드 선택) → 매장 선택 → 카테고리/아이템 브라우징 → 아이템 커스터마이징
  → (반복: 카테고리로 돌아가 더 담기) → 장바구니 확인 → 결제 → 완료 → 홈으로 복귀
```

- v1.0 초안에서는 "홈 → 매장 선택 → 모드 선택" 순서였으나, 실사용 검토 결과 **모드를 먼저 고르고 그 다음 매장을 고르는 순서**로 바뀌었다 — 홈 화면 자체가 모드 선택 화면이 되었다.
- 메뉴 선택은 v1.0에서는 "브랜드당 하나의 순차 단계열(빵→굽기→치즈→...)"이었으나, **장바구니(카트) 구조**로 바뀌었다: 카테고리별 아이템을 브라우징 → 아이템 하나를 골라 그 아이템만의 커스터마이징 진행 → 장바구니에 담기 → "메뉴 더 담기"로 반복하거나 "결제하러 가기"로 진행. 아이템에 커스터마이징 단계가 없으면(예: 단독 음료) 담기 즉시 장바구니에 들어간다.
- **탭바는 주문 흐름 진행 중(매장 선택 이후)에는 숨김** — 흐름 이탈로 인한 혼란 방지, 대신 상단에 "뒤로가기"만 노출
- 온보딩(S01)/스플래시(S00)는 아직 구현되지 않았다 — 현재는 항상 홈(모드 선택)에서 시작. 구현 시점의 우선순위 판단으로 웹 프로토타입/RN 포팅 범위에서 제외됨 (§2 참고).

## 2. 화면 목록 (v1.1, 실제 구현 기준)

| ID | 화면명 | 진입 경로 | 목적 | 이탈 조건 |
|---|---|---|---|---|
| S00 | 스플래시 | 앱 실행 | 로딩, 1초 이내 자동 전환 | **미구현** — 배포 준비 단계에서 재검토 |
| S01 | 온보딩 (최초 1회) | 최초 설치 후 | 글씨 크기/음성 기본값 설정, 앱 목적 3장 이내 소개 | **미구현** — 배포 준비 단계에서 재검토 |
| S02 | 홈 (모드 선택) | 탭바 / 앱 시작 | "연습하기"/"지금 매장이에요" 선택, 저장된 내 주문 바로가기 | 모드 버튼 탭 |
| S03 | 매장 선택 | 홈(모드 선택) 후 | 5개 매장 카드 목록, 검색창(검색 로직은 미구현) | 매장 카드 탭 |
| S04 | 카테고리/아이템 브라우징 (반복) | 매장 선택 후 / 장바구니에서 "메뉴 더 담기" | 브랜드의 카테고리별 아이템 목록, 하단에 장바구니 요약 바 | 아이템 탭(커스터마이징 있으면 S05로, 없으면 즉시 장바구니에 담김) |
| S05 | 아이템 커스터마이징 - 단계 화면 (반복) | S04 > 커스터마이징 있는 아이템 | 그 아이템만의 선택지 노출 (예: 빵→데움→야채→소스, 또는 세트→포함음료) | 마지막 단계에서 "장바구니에 담기" → S04로 복귀 |
| S06 | 장바구니 확인 | S04 > "장바구니 보기" | 담긴 라인 목록(라인별 삭제 가능), 합계 | "메뉴 더 담기"(S04) 또는 "결제하러 가기"(S07) |
| S07 | 결제 (연습모드 재현 / 실시간 안내) | S06 이후 | 실제 키오스크 결제 화면 재현(카드/페이/현금), 실결제 미처리 | 결제 방법 선택 → 완료 |
| S08 | 완료 & 저장 | S07 이후 | 장바구니 전체 요약, "내 주문으로 저장" 여부 선택 | 홈으로 |
| S09 | 내 주문 관리 | 탭바 | 저장된 주문(장바구니 스냅샷) 목록, 삭제, 이름 지정(예: "내가 좋아하는 조합") | - |
| S10 | 설정 | 탭바 | 글씨 크기, 음성 on/off, 고대비 모드, 언어(추후) | - |
| S11 | 직원 호출 안내(인라인 배너) | 실시간모드 화면에서 트리거 | "직원을 호출했어요" 안내 문구 표시 | 자동 소멸 없음(다음 화면 이동 시까지 유지) |

> v1.0 초안의 S05/S09("가상 키오스크 단계 화면"/"실시간 안내 단계 화면")는 브랜드당 하나의 순차 단계열을 전제로 했으나, 실제 구현은 카테고리별 여러 아이템을 각자 커스터마이징해서 장바구니에 담는 구조로 바뀌었다(위 S04/S05/S06). "만족도 평가"(구 S11)와 "직원 호출 확인 모달"(구 S14)은 각각 미구현, 확인 모달 없는 즉시 실행(인라인 배너)으로 단순화됐다.

## 3. 화면별 접근성 요구사항 (모든 주문 흐름 화면 공통 적용)

- 텍스트 최소 크기 18pt 이상 (설정에서 최대 200%까지 확대 가능)
- 모든 주요 버튼에 음성 안내 자동 재생 옵션 (설정에서 on/off)
- 버튼 터치 영역 최소 48x48pt
- 색상만으로 정보 구분 금지 (아이콘/텍스트 병행)
- "다시 설명해줘" 버튼은 화면 하단 고정 위치로 항상 동일한 자리에 노출 (학습 효과)

## 4. 상태(State) 설계 메모 (v1.1, 실제 구현 기준)

로컬 상태 관리는 Context/Provider 없이 **최상위 컴포넌트(`App()`)가 모든 상태를 소유하고 props로 내려주는 방식**으로 확정됐다 (웹/모바일 동일).

- **S05 (아이템 커스터마이징)**: `activeCategoryId`/`activeItemId`(어느 아이템을 커스터마이징 중인지), `itemDraftSelections`(그 아이템의 임시 선택값, 담기 완료 시 초기화), `customizeStepIndex`(그 아이템 안에서의 단계 위치) — 모두 **아이템 하나에만 스코프**된 임시 상태다.
- **S04~S06 (장바구니)**: `cart`(배열, 세션 전체를 관통하는 durable 상태) — 각 라인은 `{cartItemId, categoryId, itemId, label, customizeSelections, optionLabels, unitPrice, qty, lineTotal}`. 동일 아이템+동일 옵션은 수량(qty) 병합, 옵션이 다르면 별도 라인.
- **S07 (결제)**: 결제 관련 상태는 서버로 전송하지 않음 (개인정보/보안), 클라이언트 로컬 상태로만 처리 후 화면 종료 시 폐기
- **S08 (완료)**: "저장" 선택 시에만 그 시점의 `cart` 스냅샷을 `saved_orders`(로컬 storage — 웹은 localStorage, 모바일은 AsyncStorage)에 기록
