## 1. 배경 및 목표

기존 PRD(6.1)에서 "브랜드는 데이터"라는 원칙으로 확장성을 설계해뒀지만, 실제로 콘텐츠를 채우려면 **어떤 매장을, 어떤 기계를, 어떻게 조사해서 데이터로 옮길지**에 대한 별도의 계획이 필요하다. 이 문서는 그 리서치·콘텐츠 제작 프로세스를 정의한다.

**목표**: 실제로 존재하는 셀프주문 매장(프랜차이즈 패스트푸드/카페, 디저트카페, 일반 식당)을 조사하여, 각 매장이 사용하는 기계 형태와 메뉴 구성을 최대한 실물에 가깝게 앱 콘텐츠로 옮긴다. 사용자가 연습할 때 "진짜 그 가게에서 주문하는 것 같다"고 느끼는 것이 성공 기준이다.

## 2. 조사 대상 범위

### 2.1 매장 카테고리
| 카테고리 | 예시 | 특징 |
|---|---|---|
| 프랜차이즈 패스트푸드/카페 | 맥도날드, 롯데리아, 버거킹, 스타벅스, 투썸플레이스 등 | 대부분 키오스크, 표준화된 메뉴 구조 |
| 디저트/베이커리 카페 | 설빙, 배스킨라빈스, 파리바게뜨 등 | 키오스크 또는 카운터+태블릿 혼합 |
| 일반 식당(한식/분식/고깃집 등) | 개인·소형 프랜차이즈 식당 | **테이블오더** 비중이 높음 (키오스크는 입구, 테이블오더는 좌석에서) |

### 2.2 기계 유형
| 유형 | 설명 | 기존 지원 여부 |
|---|---|---|
| 프리스탠딩 키오스크 (`freestanding_totem`) | 세로형 무인 계산대 | ✅ 지원 (서브웨이) |
| 카운터 태블릿 (`countertop_tablet`) | 카운터 위 소형 태블릿 | ✅ 지원 (버거킹) |
| **테이블오더 (신규, `table_order`)** | 테이블에 거치된 가로형 태블릿, 좌석에서 직접 주문 | ❌ 신규 조사·설계 필요 |
| 벽걸이형 (`wall_mounted`) | 벽/카운터 상단 고정 화면 | 스키마상 정의만 되어 있음, 실사례 미조사 |

## 3. ⚠️ 설계에 영향을 주는 핵심 발견: 테이블오더는 "흐름"이 다르다

기존 ORDER_FLOW는 **단계형(빵→야채→소스→결제)**을 전제로 설계되어 있다. 그런데 테이블오더는 보통:
- 화면 왼쪽/상단에 **카테고리 탭**(예: 메인/사이드/음료/주류)이 있고
- 하나의 화면에서 **여러 메뉴를 장바구니에 계속 담았다가**
- 마지막에 **한 번에 "주문하기"**를 누르는 **장바구니형** 구조다

이건 키오스크의 "한 단계씩 진행" 방식과 근본적으로 다른 인터랙션이라, 지금 스키마(STEP이 순서대로 하나씩 진행)를 그대로 쓸 수 없다. **테이블오더 지원은 조사 후 데이터 모델을 별도로 확장하는 작업이 필요하며, 이번 조사 단계에서 실제 화면 구조를 충분히 수집한 뒤 설계를 다시 검토한다.** (섹션 7 참고)

## 4. 매장별 조사 항목 (체크리스트)

브랜드/매장 하나를 조사할 때마다 아래 항목을 채운다.

| 항목 | 설명 |
|---|---|
| 매장명 / 브랜드명 | |
| 기계 유형 | 프리스탠딩 키오스크 / 카운터 태블릿 / 테이블오더 / 벽걸이형 |
| 화면 방향 | 세로(portrait) / 가로(landscape) |
| 화면 색감·톤 | 배경색, 강조색 (브랜드 톤 참고용, 그대로 복제하지 않음) |
| 주문 진행 단계 구성 | 예: 매장/포장선택 > 메뉴선택 > 옵션선택 > 주문확인 > 결제하기 |
| 메뉴 카테고리 | 예: 버거/사이드/음료, 샌드위치/샐러드/음료 |
| 대표 메뉴 5~10개 | 메뉴명, 가격 |
| 옵션 구성 | 예: 빵 종류, 토핑, 세트 여부, 매운맛 단계 등 |
| 결제 수단 UI | 카드/페이/현금 중 화면에 노출되는 것 |
| 특이 요소 | 직원호출 버튼 유무, 다국어 지원 유무, 할인/쿠폰 입력 화면 유무 등 |
| 참고 자료 | 방문 촬영 사진(내부 참고용, 앱에는 그대로 사용 안 함) |

## 5. 콘텐츠(사진·메뉴) 소싱 원칙 — 중요

1. **실제 매장에서 촬영한 사진/화면은 내부 참고 자료로만 사용**한다. 브랜드의 로고, 메뉴 사진, 화면 UI를 그대로 앱에 넣지 않는다 (상표권/저작권 문제).
2. 앱에 실제로 들어가는 이미지는 다음 중 하나로 대체한다:
   - 자체 촬영한 일반화된 음식 사진 (브랜드 로고/포장 노출 없이)
   - 라이선스가 확인된 스톡 이미지
   - 일러스트/아이콘 기반 표현 (현재 프로토타입 방식)
3. **메뉴명·가격은 사실 기반으로 기재 가능**하지만(메뉴/가격 자체는 저작물이 아님), 화면 레이아웃과 톤은 "그 브랜드 특유의 느낌"을 재현하되 로고나 정확한 서체·그래픽을 복제하지 않는다.
4. 브랜드명은 실명을 그대로 쓸지, 익명화("A 프랜차이즈")할지는 **법무 검토 후 결정** (현재 프로토타입은 실명을 데모 목적으로만 사용 중).

## 6. 우선순위 (조사·구현 순서 제안)

### 6.1 1차 조사 대상 브랜드 (확정)

| 브랜드 | 상태 | 선정 이유 |
|---|---|---|
| 서브웨이 | ✅ 프로토타입 완료 | 옵션형(빵/토핑) 커스터마이징 흐름의 기준 사례 |
| 버거킹 | ✅ 프로토타입 완료 | 카운터 태블릿형, 어두운 톤 UI 사례 |
| **맥도날드** | 신규 조사 | 전국 매장 다수에 키오스크 도입, 어르신 키오스크 불편 사례로 언론에 가장 자주 언급되는 브랜드 |
| **롯데리아** | 신규 조사 | 국내 매장 수가 가장 많은 패스트푸드 프랜차이즈 중 하나로, 키오스크 보급률도 가장 높음 → 실사용 빈도가 높아 우선순위 높음 |
| **KFC** | 신규 조사 | 조사 대상 매장 대부분에 키오스크 도입 완료, 세트/사이드 옵션 구성이 서브웨이·버거킹과 달라 새로운 옵션 패턴 검증에 적합 |

> 출처: 업계 보도 기준 키오스크 도입 매장 수 통계(패스트푸드 프랜차이즈 무인화 현황 보도). 최신 수치는 조사 착수 시 재확인 필요.

### 6.2 전체 로드맵

| 단계 | 범위 | 목적 |
|---|---|---|
| 1차 | 프랜차이즈 패스트푸드 키오스크 3~5곳 (기존 서브웨이·버거킹 포함) | 이미 검증된 단계형 흐름을 다양한 톤으로 확장, 콘텐츠 파이프라인 정착 |
| 2차 | 카페/디저트 매장 키오스크 2~3곳 | 음료 커스터마이징(사이즈/샷추가 등) 같은 새로운 옵션 유형 검증 |
| 3차 | 테이블오더 1곳 파일럿 조사 | 장바구니형 흐름의 실제 화면 구조를 수집해 데이터 모델 재설계 근거 마련 |
| 4차 | 테이블오더 데이터 모델 확정 후 본격 확장 | 3차 결과에 따라 IA/스키마 문서 업데이트 |

> 테이블오더는 흐름 자체가 다르므로, 다른 카테고리보다 먼저 "설계 재검토"가 필요하다는 점에서 후순위로 배치했다.

## 7. 데이터 모델에 대한 예비 제안 (조사 후 확정)

- `DEVICE_PROFILE.shape`에 `table_order` 추가 (조사 완료 후 실제 사례 기반으로 세부 스타일 확정)
- `ORDER_FLOW`에 `flow_pattern` 필드 신설 제안: `"step_by_step"`(기존 키오스크형) | `"cart_based"`(테이블오더형)
  - `cart_based`인 경우 STEP 구조 대신 `CATEGORY`(카테고리) → `MENU_ITEM`(메뉴, 담기 가능 수량 포함) → `CART`(장바구니) 구조가 필요할 것으로 예상 — **정확한 구조는 3차 테이블오더 조사 완료 후 별도 설계 문서에서 확정**

|---|---|
| 상표권/저작권 침해 소지 | 섹션 5의 소싱 원칙을 콘텐츠 제작 전 전 팀원이 숙지하도록 가이드 배포 |

| 조사 인력/시간 소요 | 1차 범위를 소규모로 시작해 파이프라인이 검증된 후 확장 |
