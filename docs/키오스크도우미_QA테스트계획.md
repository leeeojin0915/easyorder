# QA 테스트 계획: 이지오더 (EasyOrder)

## 문서 정보
| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.3.6 (다이닝옵션/confirm_order/서브웨이10단계/KFC버킷·박스티어/사이즈선택/사이드·치킨 커스터마이징/맥플러리 분리 반영 — 데이터스키마 §7.6~7.12 참고) |
| 대상 | src/App.jsx (React 웹 프로토타입), mobile/ (Expo 포팅), content-pipeline (콘텐츠 데이터) |
| 작성 단계 | 테스트 (Test) |

---

## 1. 목적과 범위

지금까지 만든 프로토타입(5개 브랜드, 연습모드/실시간모드, 장바구니 주문, 저장/설정 기능)이 실제 배포 전에 갖춰야 할 품질을 검증한다. 자동화 가능한 부분은 스크립트로, 사람이 직접 조작해야 하는 부분(특히 접근성·사용성)은 체크리스트로 나눈다.

**이 문서에서 다루지 않는 것**: React Native(Expo)의 네이티브 전용 테스트(실제 TTS 동작, 스토어 심사 등)는 기술스택 문서의 배포 단계에서 별도로 다룬다.

| 실사용자(고령층) 사용성 테스트 | ❌ 수동, 실제 참가자 필요 | 섹션 9 |

## 3. 자동화된 테스트 (이미 구현됨)

```bash
npm run content:validate   # 브랜드 데이터 형식 검증 (5개 브랜드 전체)
npm run content:test       # 장바구니(cart) 로직 검증 (156개 케이스)
```

콘텐츠 파일을 추가/수정할 때마다 이 두 명령을 실행하고, 실패(❌)가 없어야 다음 단계로 진행한다. CI 파이프라인이 생기면 이 두 명령을 자동 실행 단계로 등록하는 것을 권장한다.

## 4. 기능 테스트 체크리스트 (화면별, v1.3 흐름 기준)

앱의 화면 순서는 **홈(모드 선택) → 매장 선택 → 다이닝옵션(매장식사/포장) → 카테고리/아이템 브라우징 → 아이템 커스터마이징 → 장바구니(주문확인) 확인 → 결제 → 완료** 이다. 매장 선택보다 모드 선택이 먼저 오고, 매장 선택 직후 다이닝옵션 화면이 새로 끼어든다는 점에 유의(v1.3 신규, 데이터스키마 §7.6).

### 4.1 홈 화면 (모드 선택)
- [ ] "연습하기" / "지금 매장이에요" 두 버튼이 보이는가 (매장 목록은 이 화면에 없음)
- [ ] 저장된 주문이 있을 때만 "저장된 내 주문" 섹션이 보이는가 (없으면 안 보여야 함)
- [ ] 하단 탭바(홈/내 주문/설정)가 정상 동작하는가

### 4.2 매장 선택 화면
- [ ] "연습하기"/"지금 매장이에요" 중 하나를 고른 뒤 이 화면으로 이동하는가
- [ ] 5개 매장 카드가 모두 표시되는가
- [ ] 매장 카드를 탭하면 다이닝옵션 화면으로 이동하는가
- [ ] 뒤로가기(←)로 홈(모드 선택)으로 돌아가는가

### 4.3 다이닝옵션 화면 (v1.3 신규)
- [ ] 매장 카드를 탭한 직후, 카테고리 화면보다 먼저 이 화면이 뜨는가
- [ ] "매장에서 식사" / "포장" 두 옵션이 보이는가
- [ ] 옵션을 탭하면 별도의 "다음" 버튼 없이 즉시 카테고리 화면으로 진행하는가 (실제 버거킹 키오스크의 단일 yes/no 게이트 UX와 동일)
- [ ] 뒤로가기(←)로 매장 선택 화면으로 돌아가는가
- [ ] 카테고리 화면에서 뒤로가기(←)를 누르면 매장 선택이 아니라 이 다이닝옵션 화면으로 돌아가는가

### 4.4 카테고리/아이템 브라우징 화면
- [ ] 브랜드별 카테고리(예: 버거/음료, 샌드위치/음료, KFC의 치킨/버거, 맥도날드의 맥모닝/사이드&디저트/맥카페)가 모두 보이는가
- [ ] `customize_steps`가 있는 아이템(버거 등)을 탭하면 아이템 커스터마이징 화면으로 이동하는가
- [ ] `customize_steps`가 없는 아이템(단독 음료, 롯데리아 치킨, 맥모닝/맥카페 등)을 탭하면 커스터마이징 없이 바로 장바구니에 담기는가 ("+ 담기" 표시 확인)
- [ ] 장바구니에 담긴 게 있으면 하단에 "담긴 메뉴 N개 · 금액 · 장바구니 보기" 바가 보이는가, 없으면 안 보이는가
- [ ] 뒤로가기(←)로 다이닝옵션 화면으로 돌아가는가 (매장 선택 화면이 아님, v1.3 변경)

### 4.5 아이템 커스터마이징 화면 (연습모드, 몰입형 키오스크)
- [ ] 상단 단계 표시줄이 현재 단계에 맞게 표시되는가 (매장선택 ✓ → 메뉴선택 → 주문확인 → 결제하기 → 결제완료)
- [ ] `single_select`: 하나만 선택되고, 다른 걸 누르면 이전 선택이 해제되는가
- [ ] `multi_select`: 여러 개 선택/해제가 정상 동작하는가
- [ ] `multi_select` + `max_selections`가 있는 단계(서브웨이 소스 최대 3개, KFC 치킨버킷 맛조합 최대 2개): 카운터("n/max 선택")가 표시되고, 캡에 도달하면 미선택 옵션이 비활성화(dim)되어 더 이상 선택되지 않는가 (이미 선택된 항목은 해제 가능한지도 확인)
- [ ] `binary_choice`: 두 옵션 중 하나만 선택되는가
- [ ] 아무것도 선택 안 한 상태에서 "다음"/"장바구니에 담기" 버튼이 비활성화(회색)되는가 — 단, `required: false`가 지정된 단계(서브웨이 추가토핑/야채/소스, v1.3.1 수정)는 예외로 0개 선택 상태에서도 버튼이 활성화되어야 함(토핑 안 함/야채 다 빼기/소스 없이 진행 가능해야 정상)
- [ ] "취소" 버튼이 이 아이템의 1단계로 되돌아가고 지금까지 고른 내용이 초기화되는가
- [ ] "이전" 버튼이 바로 전 단계로 돌아가고, 1단계에서는 비활성화(회색)되는가
- [ ] "이전"으로 돌아가 이미 골랐던 항목을 바꾼 뒤 "다음"으로 다시 진행하면 변경한 값이 반영되는가
- [ ] 마지막 커스터마이징 단계에서 버튼 문구가 "장바구니에 담기"로 바뀌는가
- [ ] 헤더의 ← 아이콘으로 카테고리 화면까지 나갈 수 있는가
- [ ] 하단에 "이 메뉴 가격"이 실시간으로 갱신되는가

### 4.6 장바구니(주문확인) 확인 화면
- [ ] 화면 제목/음성안내가 브랜드 JSON의 `order_steps`(confirm 타입)에 정의된 문구를 그대로 쓰는가 — 화면에 하드코딩된 문구가 아님 (v1.3에서 연결, 데이터스키마 §7.6 참고)
- [ ] 담긴 모든 라인(아이템명 + 선택 옵션 + 라인별 금액)이 정확히 표시되는가
- [ ] 라인별 삭제(휴지통 아이콘)가 정상 동작하는가
- [ ] 하단 "주문 금액"(전체 합계)이 라인 추가/삭제에 따라 정확히 갱신되는가
- [ ] "메뉴 더 담기" 클릭 시 카테고리 화면으로 돌아가는가 (장바구니 내용은 유지)
- [ ] 장바구니가 비어있으면 "결제하러 가기" 버튼이 비활성화되는가
- [ ] "결제하러 가기" 클릭 시 결제 화면으로 이동하는가

### 4.7 결제 화면 (연습모드)
- [ ] "연습 모드입니다" 문구가 항상 보이는가, 실제 결제 관련 입력(카드번호 등)을 요구하지 않는가
- [ ] 결제 금액이 장바구니 합계와 일치하는가
- [ ] 결제 방법(카드/휴대폰/현금) 중 아무거나 선택하면 완료 화면으로 이동하는가

### 4.8 실시간 안내 모드
- [ ] 다이닝옵션 화면에도 "실시간 안내" 배지가 붙어 연습모드와 다른 레이아웃으로 보이는가
- [ ] 카테고리 화면에서 "지금 눈앞의 기계 화면에서 골라주세요" 안내가 보이는가 (몰입형 키오스크 그래픽 없이)
- [ ] "다시 설명해줘" / "직원 호출" 버튼이 아이템 커스터마이징·결제 화면에서 항상 보이는가
- [ ] "직원 호출" 클릭 시 안내 문구가 뜨는가
- [ ] 장바구니(주문확인) 확인 화면이 연습모드와 다른 레이아웃(일반 앱 스타일)으로 보이는가

### 4.9 완료 화면
- [ ] 장바구니 전체 요약(아이템명, 옵션, 수량)과 총액이 정확한가
- [ ] 닉네임을 입력하지 않고 저장해도 기본 이름("{매장명} 조합")으로 저장되는가
- [ ] 저장 후 "저장했어요"로 바뀌고 입력창이 사라지는가
- [ ] "홈으로" 클릭 시 홈(모드 선택) 화면으로 이동하는가

### 4.10 내 주문 / 설정
- [ ] 저장된 주문이 없을 때 안내 문구가 보이는가
- [ ] 저장된 주문의 요약이 장바구니 기준으로 정확히 표시되는가 (여러 아이템이 있으면 모두 나열)
- [ ] 주문 삭제(휴지통 아이콘)가 정상 동작하는가
- [ ] 글씨 크기(작게/보통/크게) 변경이 화면 전체에 즉시 반영되는가
- [ ] 음성 안내 on/off 토글 시 캡션 박스가 나타나거나 사라지는가
- [ ] 고대비 모드 on/off 시 색상이 전체적으로 바뀌는가

## 5. 브랜드 전수 테스트 매트릭스

각 브랜드를 "연습모드로 처음부터 끝까지 완주"하고 "실시간모드로 처음부터 끝까지 완주"한다. 5개 브랜드 × 2개 모드 = 10개 완주 테스트.

| 브랜드 | 연습모드 완주 | 실시간모드 완주 | 비고 |
|---|---|---|---|
| 서브웨이 | [ ] | [ ] | 6종 샌드위치, **10단계 전체 완주** (빵→빵길이→치즈→추가토핑(0개 선택 가능)→토스팅→야채(0개 선택 가능)→소스(최대3, 0개 선택 가능)→단품/세트→세트사이드→세트음료) + 음료 사이즈(R/L) 선택 |
| 버거킹 | [ ] | [ ] | 6종 버거, **세트 선택 시 사이드+음료 두 단계 모두 노출되는지 확인** (조건부 스텝 2개가 같은 조건 참조), 세트 사이즈(라지 업그레이드) + **사이드 단독구매 카테고리(6종, 프렌치프라이 R/L·너겟킹 4/8조각 포함)** + 음료 사이즈(콜라/스프라이트 R/L, 아메리카노는 사이즈 없음) |
| 맥도날드 | [ ] | [ ] | 3종 버거, **세트/단품 둘 다 테스트** (세트 시 무료 음료 포함, L세트 사이즈 업그레이드) + 맥모닝/사이드&디저트/맥카페 카테고리(대부분 customize_steps 없음, **맥플러리 3종 오레오/딸기오레오/초코오레오 독립 메뉴**) + 음료·맥카페 전부 M/L 사이즈 선택 |
| 롯데리아 | [ ] | [ ] | 3종 버거, **세트/단품 둘 다 테스트** (세트 사이드 교체 포함) + **치킨 카테고리(6종, 화이어윙/치킨휠레 조각수 선택, 순살치킨 풀팩/하프팩 소스 선택 — 치킨다리/하프팩세트만 고정가)** + 음료 사이즈(R/L) 선택 |
| KFC | [ ] | [ ] | **치킨 버킷 2종(9조각/16조각) 완주**: `flavor_mix` 최대 2개(반반) 선택 확인, 3개째 시도 시 차단 확인. 기존 버거 3종은 세트/단품 둘 다 테스트, **타워버거·징거버거는 세트→박스 업그레이드까지**(오리지널 치킨버거는 박스 옵션 없음) + 음료 사이즈(M/L) 선택 |

5개 브랜드 모두 "세트를 고르지 않고도(또는 버거·치킨 없이도) 음료·사이드를 단독으로 장바구니에 담을 수 있는지"를 반드시 확인한다 — 이게 장바구니 구조 개편의 핵심 요구사항이었고, 이후 사이드/치킨 단독구매 카테고리로 확장됐다(7.10 참고). 자동 테스트(`cart.test.js`, 156개)로 이미 검증했지만, 실제 화면 전환·레이아웃까지 육안으로 재확인하는 목적.

## 6. 접근성 체크리스트

| 항목 | 확인 방법 |
|---|---|
| 텍스트 최소 크기 | "작게" 설정에서도 글자가 읽기 불편할 정도로 작아지지 않는지 |
| 버튼 터치 영역 | 모든 버튼이 최소 44~48px 높이를 유지하는지 (특히 옵션 타일, 카테고리 화면 아이템 카드) |
| 색상 대비 | 고대비 모드에서 텍스트/배경 대비가 충분한지 (일반 모드도 WCAG AA 참고) |
| 음성 안내 텍스트 | 모든 customize_steps/order_steps에 voice_text가 비어있지 않은지 (validate.js가 이미 검증) |
| "다시 설명해줘" 위치 | 실시간모드에서 항상 같은 위치에 있는지 (학습 효과) |
| 색상 단독 의존 금지 | 선택된 항목이 색상 변화 + 굵기/테두리 등 색 이외 신호도 함께 주는지 |

## 7. 데이터 저장(영속성) 테스트

- [ ] 주문을 저장한 뒤 브라우저(또는 앱)를 새로고침해도 "내 주문"에 남아있는가 (저장 항목이 `cart` 배열 기준)
- [ ] 설정(글씨크기/음성/고대비)을 바꾼 뒤 새로고침해도 유지되는가
- [ ] 저장된 주문을 삭제한 뒤 새로고침해도 삭제 상태가 유지되는가
- [ ] 저장 중 오류가 나도 앱이 멈추지 않는가 (try/catch로 방어되어 있는지 코드 확인 완료)

## 8. 엣지 케이스 체크리스트

- [ ] 아이템 커스터마이징 중 "취소"를 눌러 그 아이템의 1단계까지 초기화되는가 (장바구니에 이미 담긴 다른 라인은 영향 없어야 함)
- [ ] "이전"으로 여러 단계를 되짚어 가면서 각 단계의 선택이 그대로 남아있는가
- [ ] (맥도날드/롯데리아/KFC/버거킹) "세트"를 선택해 포함 음료 단계까지 진행한 뒤, 이전으로 돌아가 "단품"으로 바꾸고 다시 진행하면 음료 단계를 건너뛰는가 — **조건부 로직 회귀 확인**
- [ ] **(핵심)** 장바구니에 버거를 하나도 담지 않은 상태에서 음료 카테고리의 단독 음료를 담을 수 있는가 — 이번 개편의 원래 요구사항
- [ ] 같은 아이템을 동일 옵션으로 두 번 담으면 장바구니에서 수량(qty)으로 병합되는가, 옵션이 다르면(예: 같은 버거인데 하나는 세트 하나는 단품) 별도 라인으로 남는가
- [ ] 장바구니 라인을 삭제한 뒤 결제 화면의 금액도 즉시 재계산되는가
- [ ] 하나의 브랜드에서 저장했던 "내 주문"을 다른 브랜드 화면에서 열어도 요약이 꼬이지 않는가 (브랜드별 `cart` 구조가 다르므로)
- [ ] 저장된 주문이 여러 개 쌓였을 때 홈 화면의 "OO 외 N개" 표시가 정확한가
- [ ] 글씨 크기를 "크게"로 두고 옵션 이름이 긴 메뉴(예: "맥스파이시 상하이 버거", "이탈리안 비엠티")를 볼 때 레이아웃이 깨지지 않는가
- [ ] (v1.3) 서브웨이에서 "세트" 선택 후 세트사이드/세트음료 단계까지 진행한 뒤, 이전으로 돌아가 "단품"으로 바꾸면 두 단계 모두 건너뛰는가
- [ ] (v1.3) 서브웨이 소스 단계에서 3개를 고른 뒤 "이전"/"다음"으로 왔다갔다 해도 선택이 유지되고 카운터가 정확한가
- [ ] (v1.3) KFC 치킨버킷에서 맛 2개(반반)를 고른 상태로 장바구니에 담으면, 장바구니 라인의 옵션 표시가 "오리지널, 블랙라벨"처럼 선택한 두 맛이 모두 나열되는가
- [ ] (v1.3) 버거킹 와퍼에서 세트 선택 → 사이드/음료 선택 후 "이전"으로 돌아가 세트를 "단품"으로 바꾸면 사이드/음료 단계가 모두 사라지는가 (조건부 스텝 2개가 같은 조건을 참조하는 케이스)
- [ ] (v1.3) 다이닝옵션에서 "포장"을 선택한 뒤 완료 화면까지 진행해도 앱이 끝까지 정상 동작하는가 (다이닝옵션 값 자체는 현재 화면에 표시되지 않지만 흐름이 끊기지 않아야 함)

## 9. 실사용자(고령층) 사용성 테스트 계획

이 앱의 핵심 가치는 실제로 고령층이 "혼자서 주문할 수 있게 되는가"이므로, 화면이 정상 작동하는 것과는 별개로 반드시 실사용자 테스트가 필요하다.

### 9.1 참가자
- 60대 이상, 스마트폰은 사용하지만 키오스크 주문 경험이 적거나 어려움을 느낀 적이 있는 분 5~8명

### 9.2 과제 시나리오 (Task)
1. 앱을 처음 켜고, 아무 도움 없이 "연습하기" → 서브웨이를 골라 연습모드에 들어가서(매장식사/포장 선택 포함) 완주해보기
2. 완주 후 "내 주문"에 저장해보기
3. 다른 브랜드(맥도날드)를 골라 버거를 "세트"로 담고, 음료를 추가로 하나 더 단독으로 담아보기(장바구니에 2개 라인)
4. 실시간 안내 모드로 전환해서 "직원 호출" 버튼을 눌러보기
5. 설정에서 글씨 크기를 바꿔보기

### 9.3 관찰/측정 항목
- 각 과제의 완료 여부와 소요 시간
- 막히는 지점(어느 화면에서 멈칫하는지, 어떤 버튼을 못 찾는지 — 특히 "메뉴 더 담기"와 "장바구니 보기"의 구분을 이해하는지)
- 도움 요청 횟수 (진행자에게 물어본 횟수)
- 과제 완료 후 간단한 만족도(이모지 또는 5점 척도)

### 9.4 성공 기준 (PRD 2.3 KPI와 연결)
- 참가자의 80% 이상이 도움 없이 연습모드를 완주
- 평균 완료 시간이 실제 키오스크 평균 대기 허용 시간(약 2~3분) 이내
- "다시 사용하고 싶다"는 응답 비율 확인

## 10. 버그 관리
