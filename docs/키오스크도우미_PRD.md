## 1. 배경 및 문제 정의

### 1.1 배경
- 서브웨이, 맥도날드, 스타벅스 등 다수의 프랜차이즈 매장이 인건비 절감과 주문 효율화를 위해 키오스크 도입을 확대하고 있음.
- 키오스크는 빠른 주문 처리에는 유리하지만, 디지털 기기에 익숙하지 않은 고령층, 시각/인지 약자, 외국인, 최초 방문 고객에게는 진입장벽이 됨.
- 특히 서브웨이류의 "커스터마이징 주문"(빵 → 굽기 → 치즈 → 야채 → 소스 → 사이드) 매장은 선택 단계가 많아 일반 단일메뉴 키오스크보다 난이도가 훨씬 높음.

### 1.2 문제 정의
- 고령층/디지털 취약계층이 키오스크 앞에서 주문을 포기하거나, 직원 호출에 의존하거나, 매장 방문 자체를 꺼리는 상황 발생.
- 매장 입장에서도 직원이 계속 도와줘야 해서 키오스크 도입의 효율화 효과가 반감됨.

### 1.3 기회
- "그 매장 그 기계"에 특화된 사전/실시간 안내를 모바일 앱으로 제공하면, 사용자는 매장 방문 전/중에 미리 연습하거나 단계별로 안내받아 **혼자서** 주문을 완료할 수 있음.

---

## 2. 목표 (Goals)

### 2.1 비즈니스 목표
- 디지털 취약계층의 무인매장 이용률 및 만족도 향상
- 프랜차이즈 본사/가맹점과의 제휴를 통한 B2B2C 확장 가능성 확보
- (장기) 접근성 인증/ESG 사업으로 지자체·공공기관 협업 가능성

### 2.2 사용자 목표
- 키오스크 앞에서 당황하지 않고, 앱의 안내를 따라 스스로 주문을 완료
- 반복 방문 시 "내가 자주 먹는 조합"을 저장해 다음엔 더 빠르게 주문

### 2.3 성공 지표 (KPI)
| 지표 | 목표치(예시) |
|---|---|
| 앱 이용 후 주문 완료율 | 90% 이상 |
| 평균 주문 소요 시간 | 첫 이용 대비 3회차 이용 시 40% 단축 |
| 사용자 만족도(NPS) | 40 이상 |
| 재방문(재사용)율 | 월 1회 이상 이용자 30% |
| 매장 직원 개입 요청 감소율 | 도입 매장 기준 50% 감소 |

## 3. 타겟 사용자 및 페르소나

### 3.1 주요 타겟
1. **고령층 (60대 이상)**: 디지털 기기 사용에 익숙하지 않음, 글씨 작게 보임, 빠른 터치 흐름을 따라가기 어려움
2. **디지털 취약계층**: 발달장애, 경도 인지장애, 시각 저하 등
3. **외국인/관광객**: 언어 장벽 (확장 시나리오)
4. **키오스크 매장 초행자**: 특정 브랜드의 주문 방식을 처음 접하는 모든 연령

### 3.2 페르소나 예시
> **김영자님 (68세)**
> - 스마트폰은 카카오톡, 전화만 겨우 사용
> - 자녀와 함께 서브웨이에 가본 적은 있지만 혼자 주문은 못 해봄
> - "빵을 먼저 고르라는 것도 몰랐고, 화면이 계속 넘어가서 당황했다"
> - 목표: 손주와 약속한 날, 미리 가서 혼자 주문해보고 싶음

## 4. 핵심 시나리오 (User Journey) — 서브웨이 예시

### 4.1 방문 전 (사전 학습 모드)
1. 앱에서 "서브웨이" 매장 검색/선택 (GPS 기반 근처 매장 자동 추천 가능)
2. "주문 연습하기" 선택 → 실제 키오스크와 동일한 UI를 모사한 튜토리얼 진입
3. 단계별 음성 + 큰 글씨 + 그림 설명으로 빵 → 굽기 → 치즈 → 야채 → 소스 → 사이드 → **결제(가상)까지 전 과정 체험**
   - 결제 단계도 실제 키오스크 화면을 그대로 재현한 **모의(mock) 결제 화면**으로 연습 (예: "카드를 꽂으세요", "삼성페이를 태그하세요", "영수증 받기 여부 선택" 등)
   - ⚠️ 실제 카드 정보/결제는 절대 처리하지 않음 — 순수 UI 흐름 연습용이며, 화면 하단에 "연습 모드입니다"를 항상 표시
4. 연습 완료 후 "내 주문 저장" (예: 화이트빵, 미트볼, 스위트어니언 소스)

### 4.2 매장 방문 중 (실시간 안내 모드)
1. 매장 도착 → 앱이 GPS/비콘/QR로 매장 인식 (또는 사용자가 수동 선택)
2. "실시간 안내 시작" 버튼
3. 키오스크의 현재 화면과 동일한 단계를 앱이 큰 글씨/음성으로 안내
   - "지금 키오스크에 '빵 선택'이 떠 있어야 해요. 화이트빵을 눌러보세요."
4. 저장해둔 "내 주문"이 있으면 원터치로 전체 흐름을 순서대로 안내
5. 막히면 "다시 설명해줘" / "직원 호출" 버튼 제공
6. 결제 단계에서는 사전 연습 모드에서 이미 익힌 화면과 동일한 흐름을 다시 안내하되, **실제 결제는 반드시 키오스크에서 직접 진행** (앱은 결제 데이터를 처리하지 않음 — 보안/PG 이슈 회피). 이미 연습 모드로 결제 화면을 미리 경험했기 때문에 실전에서도 당황하지 않고 진행 가능

### 4.3 방문 후
1. "오늘 주문 저장하기" → 다음에 재사용
2. 만족도 간단 평가 (이모지 1개 탭)

## 5. 핵심 기능 목록 (MVP 기준)

| 우선순위 | 기능 | 설명 |
|---|---|---|
| P0 | 매장/브랜드 선택 | 검색 또는 GPS 기반 근처 매장 추천 |
| P0 | 단계별 주문 가이드(텍스트+이미지) | 실제 키오스크 화면 흐름과 1:1 매칭된 안내 콘텐츠 |
| P0 | 음성 안내(TTS) | 화면을 보기 어려운 사용자를 위한 음성 지원 |
| P0 | 큰 글씨/고대비 모드 | 접근성 기본 UI (텍스트 크기 조절, 고대비 테마) |
| P1 | 사전 연습(가상 키오스크) 모드 | 매장 방문 전 미리 시뮬레이션 (주문 전 과정) |
| P1 | 모의 결제 연습 화면 | 실제 결제 없이 결제 단계 UI(카드 삽입, 페이 태그, 영수증 선택 등)까지 연습. 실 결제 데이터 미처리 |
| P1 | 내 주문 저장/재사용 | 자주 먹는 조합 저장 |
| P1 | "다시 설명해줘" 버튼 | 현재 단계 재설명 |
| P2 | 매장 직원 호출 연동 | 앱에서 직원 호출 요청 (매장 제휴 필요) |
| P2 | 다국어 지원 | 외국인 사용자 대응 |
| P2 | 보호자 연동 모드 | 가족이 원격으로 진행상황 확인/도움 |

### MVP 범위 확정 (제안)
- **브랜드 1개(서브웨이)만 우선 출시**, 단 **처음부터 다른 브랜드를 계속 추가할 수 있는 구조로 설계** (아래 6.1 확장 가능한 콘텐츠 아키텍처 참고)
- 실시간 매장 연동(비콘/POS 연동) 없이, **앱 자체 콘텐츠로 단계 안내**하는 방식으로 시작 (기술 난이도/제휴 부담 최소화)
- 실제 결제는 앱이 대행하지 않음 (법적/PG 이슈 회피). 단, **결제 단계의 UI 흐름은 모의(mock) 연습으로 제공**하여 사용자가 실전에서 결제까지 당황 없이 진행할 수 있도록 함

## 6. 비기능 요구사항 (Non-Functional Requirements)

| 항목 | 요구사항 |
|---|---|
| 접근성 | WCAG 2.1 AA 수준 준수, 텍스트 크기 최대 200%까지 조절, 음성 안내 필수 |
| 성능 | 화면 전환 1초 이내, 음성 안내 지연 2초 이내 |
| 오프라인 지원 | 사전 다운로드한 매장 가이드는 오프라인에서도 열람 가능 |
| 플랫폼 | iOS / Android (하이브리드 또는 네이티브, 설계 단계에서 결정) |
| 사용성 | 첫 사용자도 별도 교육 없이 3단계 이내로 핵심 기능 도달 가능해야 함 |
| 개인정보 | 저장 주문 정보는 로컬 우선 저장, 서버 저장 시 최소 수집 원칙 |

### 6.1 확장 가능한 콘텐츠 아키텍처 (필수 설계 원칙)
MVP는 서브웨이 1개 브랜드만 지원하지만, **브랜드/매장을 앱 재배포(업데이트) 없이 계속 추가할 수 있어야 함**. 이를 위해 설계 단계에서 아래 원칙을 반드시 반영:

- **브랜드/매장을 "데이터"로 관리**: 코드에 서브웨이 로직을 하드코딩하지 않고, 매장별 주문 단계(빵→굽기→치즈→...)를 JSON/서버 콘텐츠로 정의해 앱이 이를 읽어 렌더링하는 구조 (예: `store_id`, `flow_steps[]`, `options[]` 스키마)
- **공통 UI 컴포넌트 + 매장별 콘텐츠 분리**: "선택지 화면", "음성 안내", "모의 결제 화면" 등은 공통 컴포넌트로 만들고, 브랜드마다 다른 것은 텍스트/이미지/단계 순서 등 콘텐츠 데이터로만 교체
- **콘텐츠 관리(CMS) 여지 확보**: 새 브랜드 추가 시 개발자 없이도(또는 최소 개발로) 콘텐츠 입력만으로 추가 가능하도록, 추후 관리자용 콘텐츠 등록 도구를 고려
- **단계 유형의 표준화**: "단일 선택", "다중 선택(토핑 등)", "결제 흐름" 등 매장마다 반복되는 단계 유형을 몇 가지 표준 템플릿으로 정의해두면, 새 브랜드 추가 시 대부분의 단계는 템플릿 재사용으로 처리 가능

> 이 원칙은 설계(Design) 단계에서 데이터 스키마와 화면 컴포넌트 구조로 구체화할 예정입니다.

## 7. 제약사항 및 리스크

| 리스크 | 내용 | 대응 방안(초안) |
|---|---|---|
| 매장 UI 변경 | 프랜차이즈가 키오스크 UI를 업데이트하면 앱 가이드가 불일치 | 콘텐츠를 서버에서 관리해 앱 업데이트 없이 갱신 가능하도록 설계 |
| 실시간 연동 부재 | 초기 MVP는 실제 키오스크 화면과 자동 동기화되지 않음 | 사용자가 수동으로 "다음 단계" 넘기는 방식으로 우선 대응, 추후 매장 제휴로 고도화 |
| 매장별 편차 | 같은 브랜드도 지점마다 옵션/화면이 다를 수 있음 | 초기엔 표준 매뉴 기준으로 제작, 지점별 차이는 사용자 피드백으로 보완 |
| 타겟 사용자의 앱 진입장벽 | 정작 고령층이 앱 설치/사용 자체를 어려워할 수 있음 | 온보딩 극단순화, 보호자가 대신 설치해주는 시나리오 지원 |

---

## 8. 향후 로드맵 (제안)

1. **1단계 (MVP)**: 서브웨이 1개 브랜드, **확장 가능한 콘텐츠 아키텍처**로 구축 + 음성/큰글씨 + 모의 결제 연습 포함
2. **2단계**: 내 주문 저장, 사전 연습 모드 고도화, **콘텐츠 데이터 추가만으로 브랜드 확장**(맥도날드, 스타벅스 등)
3. **3단계**: 매장 제휴(비콘/QR)로 실시간 화면 동기화, 직원 호출 연동
4. **4단계**: 다국어, 보호자 연동, 지자체/공공기관 협업
